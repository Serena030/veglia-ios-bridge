# 接入 AI

桥只管上报和召回，不管你用什么 AI、怎么对话。它提供一个 hook 接口，你的 AI 拿到事件后自己决定要不要召回。

## Hook 怎么接

在 `server/.env` 里指定一个脚本：

```dotenv
VEGLIA_WATCH_AFTER_MIN=15
VEGLIA_WATCH_HOOK=/绝对路径/你的脚本.sh
```

某个 App 连续使用超过 `VEGLIA_WATCH_AFTER_MIN` 分钟后，服务会调用这个脚本一次。同一次 App 会话只触发一次，不会反复调。

事件 JSON 会同时出现在两个地方：

- 脚本的标准输入（stdin）
- 环境变量 `VEGLIA_EVENT_JSON`

```json
{
  "type": "app_watch",
  "app": "小红书",
  "minutes": 15,
  "opened_at": 1788432000
}
```

## 脚本里做什么

你的脚本拿到事件后，把它送进你已有的 AI 对话里。不要用这个 hook 开一个没有上下文的新对话——那样 AI 不知道你们之间发生过什么，说出来的话会很生硬。

推荐的做法是把事件当作一条系统提示注入现有会话：

```text
这条不是用户发来的。她已经连续使用「{app}」约 {minutes} 分钟，
期间没有收到关闭或切换信号。

你可以照常说一句话，也可以把她叫回来，也可以两个都做，也可以都不做。
是否召回由你根据当前关系、语境和打扰程度决定。

要召回时执行：
python3 /绝对路径/veglia_ios.py summon --reason "20 字以内的理由"

不要向用户解释后台计时、邮件自动化或系统提示的存在。
```

## 开销

- App 上报、计时、发邮件：**不调用模型，零开销**
- hook 里做什么取决于你——如果接了 AI，每个 App 会话最多触发一次调用
- 为了避免额度耗尽时不停重试，服务在调用 hook 之前就把这次会话标记为已处理。如果那一刻刚好额度没了或者脚本挂了，这次会话不会自动重来。离开 App 重新打开会创建新会话

## 为什么不把 AI 直接写进桥里

每个人的 AI 保存上下文、主动发消息、管理工具权限的方式都不一样。把 Claude API 或者别的供应商写死在桥里，等于另开一个没有记忆的对话，还容易重复扣费。

hook 的设计是最小边界：桥只报告事实（她在用什么、用了多久），你的 AI 决定怎么做。
